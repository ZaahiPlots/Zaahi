## Root cause — found in STEP 0

The 5-iteration "flat grey then totally blank" investigation logged in
`docs/research/signature-realistic-2026-06-10.md` §10 was NOT any of
the six hypotheses listed there.

It was a **MapLibre v4 → v5 CustomLayer API breaking change**:

  v4: `render(gl: WebGLContext, matrix: number[16])`
  v5: `render(gl: WebGLContext, args: CustomRenderMethodInput)`
      where `args.defaultProjectionData.mainMatrix` is the v4-equivalent.

The old code did:
```ts
camera.projectionMatrix = new THREE.Matrix4()
  .fromArray(matrix as unknown as ArrayLike<number>)
  .multiply(modelMatrix);
```

Under MapLibre v5, `matrix` arrives as
`{ defaultProjectionData, modelViewProjectionMatrix, projectionMatrix,
shaderData, farZ, nearZ, fov, ... }` — a plain object with no `.length`.
`THREE.Matrix4().fromArray()` silently reads indices 0..15 as
`undefined` → produces a NaN matrix → projection collapses to outside
clip space → silent no-render. No error, no log.

STEP 0 of the §10 PROTOCOL — rebuild the official MapLibre + Three.js
custom-layer example from scratch — reproduced the bug in the
**verbatim official MapLibre example** on the first run (red 60×60×80 m
MeshBasicMaterial debug cube at project origin: not visible). Adding
diagnostic `matrix[0].toFixed(6)` instantly produced
`Cannot read properties of undefined (reading 'toFixed')` — root cause
located in 90 seconds of bisection.

The fix (committed as part of `5a80093`):
```ts
let flat: ArrayLike<number> | null = null;
if (args && (Array.isArray(args) || args instanceof Float32Array || args instanceof Float64Array)) {
  flat = args as ArrayLike<number>;
} else if (args && typeof args === "object") {
  const obj = args as Record<string, unknown>;
  const cand =
    (obj.defaultProjectionData as Record<string, unknown> | undefined)?.mainMatrix ??
    obj.modelViewProjectionMatrix ??
    obj.mainMatrix ??
    obj.projectionMatrix ??
    obj.matrix ??
    null;
  if (cand) {
    if (Array.isArray(cand) || cand instanceof Float32Array || cand instanceof Float64Array) {
      flat = cand as ArrayLike<number>;
    } else if (typeof cand === "object") {
      const arr = new Array<number>(16);
      const indexed = cand as Record<string, number>;
      for (let i = 0; i < 16; i++) arr[i] = indexed[i];
      flat = arr;
    }
  }
}
if (!flat) return;
// ... existing modelMatrix + camera.projectionMatrix code unchanged.
```

None of the six §10 hypotheses (resetState ordering / ShaderMaterial →
RawShaderMaterial / matrix multiplication order / outputColorSpace
pinning / camera.matrixWorldInverse staleness / scene-vs-camera up-
vector mismatch) were ever needed. They were all premised on the
matrix arriving correctly, which it didn't.
